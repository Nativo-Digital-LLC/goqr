# Fase 3 — Panel del dueño: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rehacer el panel `/dashboard/*` con shadcn y el diseño del canvas: resumen, editor del menú (con vista previa), edición de producto, establecimiento y código QR, en escritorio y celular. Al terminar, el panel reemplaza la edición que la fase 2 quitó del menú público.

**Architecture:** Un `PanelLayout` nuevo protege las rutas, carga los establecimientos del dueño y expone el elegido por contexto (`usePanel()`). Cada pantalla vive en `src/pages/panel/`. Las escrituras reutilizan los servicios existentes (`categories`, `subcategories`, `products`, `establishments`), con tres ajustes: reordenar con un `writeBatch`, permitir quitar la foto de un producto y permitir subcategorías sin foto. Meilisearch ya se sincroniza en el servidor (Functions `modules/search.ts`), así que el cliente no escribe en el índice. La lógica pura (horarios por día, días de prueba, checklist, conteo de traducciones, reordenar) va en `src/lib/panel.ts` y `src/lib/schedule.ts` con pruebas.

**Tech Stack:** React 18, TypeScript, Tailwind v4, shadcn (`src/components/ui`), react-hook-form + zod, sonner, lucide-react, `qrcode`, Firebase (Auth, Firestore, Storage), vitest.

**Spec:** `docs/superpowers/specs/2026-11-19-goqr-relaunch-design.md` (fase 3: "Panel: resumen, editor del menú, establecimiento, QR"). Diseño: `docs/design/PanelHome.dc.html`, `PanelMenuEditor.dc.html`, `PanelProductEdit.dc.html`, `PanelEstablishment.dc.html`, `PanelQR.dc.html`, `PanelMobile.dc.html`.

## Global Constraints

- Rama `fase-3`, creada sobre `fase-2`. **No se despliega** hasta que el usuario lo apruebe (las fases 2 y 3 salen juntas); no hacer push.
- Indentación con tabs. Todo el texto visible en español (RD) con acentos. Sin WhatsApp de GoQR: la ayuda es `mailto:contacto@goqr.com.do`.
- Tokens de `src/styles/tokens.css`; botón primario del panel en cacao (`bg-primary`), acento tomate (`brand`). Componentes con borde llevan `border-border`. Botones con `loading` mientras guardan.
- Archivos nuevos sin `antd`, `@ant-design/icons` ni `sweetalert2`. Avisos con `sonner`; confirmaciones con `Dialog` de shadcn.
- El cliente nunca escribe `billing`, `isActive` ni `userId` en un update (las reglas lo rechazan). `updateEstablishment` debe recibir solo los campos editados.
- Soft-delete: borrar = `deletedAt: new Date()`. Nada se borra de verdad.
- Nombres bilingües: al editar se conservan `es_*` y `en_*`. El inglés es opcional (si falta, el menú muestra el español).
- Sin dependencias nuevas: el orden se cambia con botones subir/bajar (no arrastrar); "PDF para imprimir" abre la plantilla en una página de impresión del navegador (`window.print()`); las plantillas se descargan como PNG generado en `<canvas>`.
- El QR codifica `qrSrc(slug)` (`https://goqr.com.do/m/:slug?src=qr`) de `src/lib/qr.ts`.
- Estadísticas (fase 7) y Plan y pagos (fase 4) no se construyen aquí: su entrada del menú lleva a una página corta que lo explica; el resumen no muestra el bloque de estadísticas.
- Hooks de acción siguen el patrón `[handler, loading, error]`.
- Pruebas: funciones puras con vitest. No se escriben pruebas de páginas con RTL; la UI se verifica en el navegador (el controlador usa Chrome sin ventana).
- Commits terminan con `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Dueño con varios establecimientos: al cambiar de establecimiento, ninguna pantalla muestra ni guarda datos del anterior (formularios se reinician). → Task 3 (contexto con `key` por id) y revisión en Tasks 5–9.
2. Guardar un establecimiento sin tocar `billing`/`isActive`/`userId`, y con datos viejos (sin `schedules`, `socialNetworks`, `exactColor`, `googlePlaceId`): el formulario carga sin romperse y guarda solo lo que cambió. → Task 8.
3. Horarios viejos con días o horas en formatos raros ("Lun", "8:00am"): el editor no los borra al guardar otra sección; los que no entiende los conserva tal cual. → pruebas en Task 1, uso en Task 8.
4. Reordenar o borrar mientras otra escritura está en curso, o fallar a mitad: el orden queda consistente (batch) y la lista se recarga del servidor. → Task 2 y Task 5.
5. Cambiar el enlace del menú (`domain`) a uno ocupado o inválido: no se guarda, se avisa, y el QR viejo deja de servir solo si el dueño lo confirma. → Task 8.

### Task 1: Lógica pura del panel

**Files:**
- Create: `src/lib/schedule.ts`, `src/lib/schedule.test.ts`, `src/lib/panel.ts`, `src/lib/panel.test.ts`

**Interfaces:**
- Consumes: `parseDays`, `parseHours`, `dayLabel` de `src/lib/menu.ts`; tipos `ScheduleProps`, `EstablishmentProps`, `ProductProps`.
- Produces (`src/lib/schedule.ts`):
  - `type DayHours = { open: boolean; from: string; to: string }` (horas `"h:mm A"`, p. ej. `"8:00 AM"`).
  - `type Week = DayHours[]` (7 entradas, lunes = 0).
  - `schedulesToWeek(schedules: ScheduleProps[] | undefined): { week: Week; unparsed: ScheduleProps[] }` — cada fila con días y horas legibles marca esos días abiertos con su rango (si un día tiene varias filas, se usa la primera); las filas ilegibles van a `unparsed` sin tocar. Días sin fila: `{ open: false, from: '8:00 AM', to: '10:00 PM' }`.
  - `weekToSchedules(week: Week, unparsed?: ScheduleProps[]): ScheduleProps[]` — agrupa días abiertos con el mismo `from`/`to` en una fila `{ days: 'Lunes, Martes', hours: '8:00 AM - 10:00 PM' }` (días en orden de la semana, nombres en español con acento, separados por `", "`), en el orden del primer día de cada grupo, y añade `unparsed` al final.
  - `copyMondayToAll(week: Week): Week`.
  - `to24(h: string): string` y `from24(hhmm: string): string` — conversión entre `"h:mm A"` y `"HH:mm"` (para `<input type="time">`).
- Produces (`src/lib/panel.ts`):
  - `trialDaysLeft(trialEndsAt: { toDate(): Date } | Date | undefined | null, now: Date): number | null` — días enteros restantes redondeando hacia arriba, mínimo 0; `null` sin fecha.
  - `setupChecklist(e: EstablishmentProps, productCount: number): { brand: boolean; products: boolean; qr: boolean; share: boolean }` — `brand` si hay `logoUrl` y `bannerUrl`; `products` si `productCount >= 5`; `qr`/`share` se leen de `localStorage` (`goqr:qr-downloaded:<id>`, `goqr:link-copied:<id>`) con valor `'1'`.
  - `untranslatedCount(products: Pick<ProductProps, 'en_name'>[]): number` — productos sin `en_name` (vacío o null).
  - `moveItem<T>(items: T[], index: number, delta: -1 | 1): T[]` — copia con el elemento movido; fuera de rango devuelve la misma lista.
  - `ordersAfterMove<T extends { id: string }>(items: T[]): { id: string; order: number }[]` — `order` = índice + 1.

  - `copyMondayToAll` copia `open/from/to` del lunes a los 7 días.
